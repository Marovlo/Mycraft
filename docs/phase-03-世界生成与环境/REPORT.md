## 光照系统架构（核心改动）

```
数据层: Chunk.lightData_[65536] (每 byte packed: skyLight<<4 | blockLight)
        Chunk.heightMap_[256]   (每列最高不透明方块 Y)
传播层: LightEngine::initSkyLight()         — 区块生成时天空光 BFS
        LightEngine::initBlockLight()        — 区块生成时方块光 BFS
        LightEngine::updateAfterBlockChange() — 动态光照重算（挖掘/放置触发）
Mesh层: addFace(pos, dir, texId, light)      — 查询邻居光照 → 顶点 light
GPU层:  Vertex { position, normal, texCoord, light }  — 36 bytes (从32扩展)
着色器: fragLight × faceShade                — 替代硬编码方向光
曲线:   MC 指数亮度 0.8^(15-level)           — level 0=0.05, 15=1.0
```

**动态更新流程**（`updateAfterBlockChange`）：
1. 清除变更点 R=16 范围内所有光照
2. 重新从天空向下灌入 skyLight=15
3. 从边界收集仍有光照的邻居作为 BFS 种子
4. 分别 BFS 传播天空光和方块光
5. 标记受影响 chunk 为 meshDirty

## 第四阶段准备情况

**可直接开始**：
- 序列化框架（纯 C++ 数据读写，不依赖新渲染功能）
- 区块持久化（Chunk 数据结构已稳定，blocks_ + lightData_ 可直接序列化）
- 玩家数据保存（Player 所有字段已定义完毕）

**需要注意**：
- Chunk 数据量大（blocks_=128KB + lightData_=64KB），需要调色板压缩
- 光照数据可选择是否持久化（不存 = 加载时重算，存 = 加载更快但文件更大）
- 建议先做：不存光照，加载时重新 initSkyLight + initBlockLight，避免格式耦合
