# 第五阶段：生物与 AI — 详细开发文档

> **目标**：为世界添加生命。实现被动生物（猪、牛、羊、鸡）和敌对生物（僵尸、骷髅、蜘蛛、苦力怕），
> 包含完整的 AI 寻路、生成规则、战斗系统和掉落物。完成后世界不再空旷，玩家有了真正的生存压力。
>
> **前置条件**：Phase 1-4 全部完成（渲染管线、物品系统、存档、多线程区块）。
> **关键约束**：生物数量可能很多（数百只），必须从一开始就考虑性能。

---

## 实施批次与依赖关系

```
Batch 1: 生物基础框架（Entity 扩展 + 渲染 + 碰撞）
    │

```

## Batch 1：生物基础框架

### 需求分析
当前 Entity 系统只支持掉落物实体（ItemEntity）。需要扩展为通用的生物实体框架，
支持不同体型、碰撞箱、生命值、AI 行为。

### 核心数据结构

**MobEntity**（继承 Entity）：
```cpp
struct MobEntity : Entity {
    // 基础属性
    int hp, maxHp;
    float moveSpeed;
    float attackDamage;
    float attackRange;
    int attackCooldown;

    // 碰撞箱（AABB）
    float width, height;  // 猪: 0.9×0.9, 僵尸: 0.6×1.95

    // AI 状态
    AIState aiState;
    Entity* target;       // 追踪目标
    glm::vec3 wanderTarget;

    // 动画
    float walkCycle;      // 0-1 循环，控制腿部摆动
    float hurtTicks;
    bool onGround;
};
```

**MobType 枚举**：
```cpp
enum class MobType : uint8_t {
    Pig, Cow, Sheep, Chicken,           // 被动
    Zombie, Skeleton, Spider, Creeper,  // 敌对
    COUNT
};
```

**MobRegistry**：单例，注册每种生物的默认属性（类似 BlockRegistry/ItemRegistry）。

### 渲染方案

MC 原版生物使用分部件的长方体模型（头、身体、四肢）。我们采用相同方案：

**MobModel**：每种生物定义一组长方体部件（Cuboid），每个部件有：
- 位置偏移、尺寸、旋转轴心
- UV 映射到生物纹理图（每种生物一张 64×32 或 64×64 PNG）
- 动画：行走时腿部绕 X 轴摆动，受伤时整体闪红

**MobRenderer**：
- 每帧收集所有可见生物，构建顶点数据
- 使用与方块相同的着色器（position + normal + UV + light）
- 每种生物一张纹理 → 需要纹理数组或 atlas 扩展

### 碰撞检测
- 生物与方块：复用 Physics 模块的 AABB-方块碰撞
- 生物与玩家：AABB 相交检测
- 生物之间：简化为圆柱体推挤（避免重叠）

### 新增文件
- `src/entity/mob_entity.h` — MobEntity 结构体
- `src/entity/mob_registry.h/.cpp` — MobRegistry 单例
- `src/renderer/mob_model.h/.cpp` — 生物模型定义
- `src/renderer/mob_renderer.h/.cpp` — 生物渲染器

## Batch 2：AI 基础

### 状态机

每种生物的 AI 由有限状态机（FSM）驱动，状态之间根据条件转换：

```
被动生物:
  Idle ←→ Wander ←→ Flee (受伤后逃跑)
       ↕
     Panic (着火/受伤)

敌对生物:
  Idle ←→ Wander → Detect → Chase → Attack
                              ↑        ↓
                              └── Cooldown
```

**AIState 枚举**：
```cpp
enum class AIState : uint8_t {
    Idle,       // 站立不动（1-4 秒随机）
    Wander,     // 随机方向缓慢移动
    Flee,       // 远离伤害源
    Chase,      // 追踪玩家
    Attack,     // 攻击动画中
    Cooldown,   // 攻击后冷却
};
```

### 寻路

**简化 A* 寻路**：
- 网格化：以方块为单位的 2D 网格（忽略 Y 轴复杂地形，只检查脚下方块是否可行走）
- 可行走判断：脚下是实心方块 + 头部两格是空气
- 路径长度限制：最多 16 格（避免长距离寻路的性能开销）
- 缓存：每 20 tick 重新寻路一次（不是每 tick）

**导航辅助**：
- 跳跃检测：前方 1 格高障碍 → 自动跳跃
- 悬崖检测：被动生物不会走下 3 格以上的悬崖
- 水域检测：陆地生物避开水

### 新增文件
- `src/ai/ai_state.h` — AIState 枚举 + 状态转换逻辑
- `src/ai/pathfinder.h/.cpp` — 简化 A* 寻路器
- `src/ai/mob_ai.h/.cpp` — 生物 AI tick 逻辑

|------|-----------|-----|------|--------|----------|
| 猪 | 0.9×0.9 | 10 | 0.25 | 生猪排 1-3 | 受伤逃跑 |
| 牛 | 0.9×1.4 | 10 | 0.2 | 生牛排 1-3, 皮革 0-2 | 受伤逃跑 |

### AI 行为
- **Idle**：站立 2-6 秒，随机转头
- **Wander**：随机选择 4-8 格内的目标点，缓慢移动
- **Flee**：受到伤害后，以 1.5 倍速度远离攻击者，持续 3-5 秒

### 生成规则（简化版，Batch 6 完善）
- 草地/森林群系，亮度 ≥ 9
- 每个区块最多 4 只被动生物
- 初始世界生成时在地表随机放置

## Batch 4：敌对生物

### 生物列表

| 生物 | 体型 (W×H) | HP | 攻击力 | 移速 | 追踪距离 | 特殊能力 |
|------|-----------|-----|--------|------|---------|----------|
| 僵尸 | 0.6×1.95 | 20 | 3 | 0.23 | 40 格 | 阳光下燃烧 |
| 骷髅 | 0.6×1.99 | 20 | 2-5 | 0.25 | 16 格 | 射箭（远程）|
| 蜘蛛 | 1.4×0.9 | 16 | 2 | 0.3 | 16 格 | 爬墙, 白天中立 |
| 苦力怕 | 0.6×1.7 | 20 | 爆炸 | 0.25 | 16 格 | 接近后 1.5 秒爆炸 |

### AI 行为
- **Detect**：检测范围内的玩家（视线检查 + 距离检查）
- **Chase**：A* 寻路追踪玩家，每 20 tick 更新路径
- **Attack**：
  - 僵尸/蜘蛛：近战，接触伤害 + 击退
  - 骷髅：16 格内射箭（箭矢实体）
  - 苦力怕：接近 3 格内开始膨胀，1.5 秒后爆炸（破坏方块 + 范围伤害）

### 阳光燃烧
- 僵尸/骷髅在 skyLight ≥ 12 且头顶无遮挡时着火
- 着火：每秒 1 点伤害，持续到进入阴影或死亡
- 需要昼夜循环系统（Batch 8）

## Batch 5：战斗系统

### 玩家攻击生物
- 左键点击：对准星指向的生物造成伤害
- 伤害值 = 手持武器的 attackDamage（空手 = 1）
- 攻击冷却：0.5 秒（10 tick）
- 击退：被击中的生物沿攻击方向推开
- 暴击：跳跃下落时攻击 → 伤害 ×1.5

### 生物攻击玩家
- 近战：生物碰撞箱与玩家碰撞箱重叠时触发
- 远程：箭矢实体碰撞检测
- 伤害减免：护甲值（Phase 2 预留的装备系统）
- 无敌帧：受伤后 0.5 秒内不再受伤（防止连续伤害）

### 击退公式（MC 原版）
```
knockbackX = -sin(attackerYaw) * knockbackStrength
knockbackY = 0.4
knockbackZ = cos(attackerYaw) * knockbackStrength
```

### 死亡动画
- 生物 HP ≤ 0 → 倒地动画（绕 X 轴旋转 90°）→ 0.5 秒后消失
- 消失时生成掉落物实体

## Batch 6：生物生成规则

### 生成条件（对标 MC 原版）

**被动生物**：
- 亮度 ≥ 9（skyLight 或 blockLight）
- 脚下是草方块
- 初始世界生成时放置，之后不再自然生成（MC 原版行为）

**敌对生物**：
- 亮度 ≤ 7
- 距离玩家 24-128 格
- 每 400 tick 尝试一次生成
- 区域内敌对生物上限：根据加载区块数计算（约 70 只）

### 生成算法
1. 在玩家周围 24-128 格范围内随机选择位置
2. 检查亮度、方块类型、空间是否足够
3. 检查区域生物上限
4. 生成 1-4 只同种生物（群体生成）

### 消失规则
- 距离玩家 > 128 格 → 立即消失
- 距离玩家 > 32 格 → 每 tick 1/800 概率消失
- 被命名的生物不消失（未来功能）

## Batch 7：生物掉落物 + 经验值

### 掉落表
每种生物定义掉落表（LootTable），包含：
- 物品 ID、数量范围、概率
- 特殊条件（如用火烧死 → 掉落熟肉）

### 经验值（可选延后）
- 击杀生物获得经验球
- 经验球是实体，飞向玩家并被拾取
- 经验值用于附魔（Phase 7）

---

## Batch 8：昼夜循环

### 时间系统
- 一个 MC 日 = 24000 tick = 20 分钟
- 时间段：日出(0-1000) → 白天(1000-12000) → 日落(12000-13000) → 夜晚(13000-23000) → 日出

### 天空颜色
- 根据时间插值天空颜色（蓝 → 橙 → 深蓝 → 黑）
- 修改 fogColor 和 clearColor

### 光照影响
- skyLight 乘以时间因子：白天 ×1.0，夜晚 ×0.25
- 影响生物生成和植物生长

### 月相
- 8 种月相，影响史莱姆生成概率（未来）
