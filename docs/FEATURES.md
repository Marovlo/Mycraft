# Mycraft 功能开发路线图

> 本文档对标原版 Minecraft Java Edition，按**开发优先级**排序。  
> 每个功能标注 `[已完成]` `[部分完成]` `[未开始]` 状态。  
> 优先级原则：**引擎基础 → 核心玩法 → 世界环境 → 持久化 → 生物AI → 内容扩展 → 高级系统 → 润色优化**

### 核心设计原则

1. **存档系统先行设计**：每个新系统加入时，必须**同步定义其序列化格式**。数据结构要在前期设计周到，避免后期大规模重构。
2. **渐进式持久化**：存档系统随开发阶段逐步扩展保存的数据类型（详见第四阶段）。
3. **性能优先**：在正确性前提下，始终考虑性能。
4. **面向最终目标的架构**：不写一次性代码，每个系统都要考虑后续扩展。

## 第四阶段：存档与持久化（基础设施，尽早落地）

> **设计哲学**：存档系统不是"做完了最后加上去"的功能，而是贯穿整个开发过程的基础设施。
> 每新增一个系统（物品、生物、红石...），都必须同步在序列化层定义其数据格式。
> 本阶段建立框架和核心格式，后续阶段渐进扩展。

### 4.1 序列化框架 [未开始]
- [ ] **二进制序列化库**：定义通用的读写接口（`Serializer` / `Deserializer`）
- [ ] **NBT 格式实现**：支持 Compound、List、Int、String、ByteArray 等标签类型
  - 选择 NBT 是因为与 MC 兼容，且可读性好（可导出为 SNBT 文本调试）
  - 也可先用简化二进制格式，但接口要预留 NBT 兼容
- [ ] **版本号机制**：每个存档文件头包含格式版本号，用于向后兼容和数据迁移

### 4.2 区块持久化 [未开始]
- [ ] **区块序列化**：方块数据（调色板压缩 + 索引数组）、光照数据、方块实体
  - 调色板压缩：区块内只用 N 种方块 → 存调色板 + 每方块 log2(N) bit 索引
  - 比直接存 uint16_t × 65536 省 80%+ 空间
- [ ] **区域文件系统**：32×32 区块合并为一个 `.mca` 文件
  - 文件头 8KB 索引表（每区块 4 字节偏移 + 1 字节扇区数）
  - 区块数据 zlib/lz4 压缩后写入
- [ ] **脏区块追踪**：只保存修改过的区块，未修改的不写磁盘
- [ ] **按需加载**：玩家接近时从磁盘加载区块，远离时卸载并保存

### 4.3 世界元数据 [未开始]
- [ ] **level.dat**：世界名称、种子、游戏模式、难度、时间（刻）、天气状态、世界生成器参数
- [ ] **玩家数据**：位置、朝向、生命值、饱食度、经验、背包内容、游戏模式
  - 单人：存入 level.dat
  - 多人预留：`playerdata/<uuid>.dat`
- [ ] **存档目录结构**：
  ```
  saves/<世界名>/
  ├── level.dat              # 世界元数据
  ├── level.dat_old          # 备份
  ├── region/                # 主世界区块
  │   ├── r.0.0.mca
  │   └── ...
  ├── DIM-1/region/          # 下界（预留）
  ├── DIM1/region/           # 末地（预留）
  └── playerdata/            # 多人玩家数据（预留）
  ```

### 4.4 保存与加载流程 [未开始]
- [ ] **自动保存**：每 5 分钟（或每 6000 刻）保存所有脏区块 + 玩家数据
- [ ] **退出保存**：关闭游戏时完整保存
- [ ] **增量保存**：每帧保存少量脏区块（如每帧 2 个），分摊 IO 压力
- [ ] **异步 IO**：磁盘读写在独立线程执行，不阻塞主线程/渲染
- [ ] **崩溃恢复**：写入前先写临时文件，完成后原子替换（防止写到一半断电损坏存档）

### 4.5 世界管理界面 [未开始]
- [ ] **创建世界**：输入世界名称、种子（可选）、游戏模式
- [ ] **世界列表**：扫描 saves/ 目录，显示世界名、最后游玩时间、大小
- [ ] **删除世界**：确认后删除存档目录

### 4.6 各阶段存档数据扩展计划

> 以下表格定义每个系统上线时需要新增的持久化数据，确保不会遗漏。

| 第三阶段 | 群系 | 区块群系ID数组 |
| 第三阶段 | 光照 | 区块光照数据（方块光+天空光，每方块各4bit） |

## 建议的下一步开发顺序

基于依赖关系和游戏体验的重要性：

1. **纹理加载系统** — 所有视觉效果的基础
2. **光照系统** — 极大提升视觉效果和游戏性（敌对生物生成依赖）
3. **天空盒 + 雾效** — 让世界看起来"完整"
4. **Tick 系统** — 其他动态系统（流体、AI、生长）都依赖
5. **序列化框架 + 区块持久化** — 尽早落地，后续所有系统同步扩展
6. **物品 + 背包系统** — 核心玩法基础（同步定义物品序列化格式）
7. **制作系统** — 有了物品后即可实现
8. **工具和武器** — 挖掘和战斗的核心（同步定义耐久序列化）
9. **GUI 系统（HUD + 容器）** — 玩家需要看到信息、操作物品
10. **生命值 + 饱食度** — 生存玩法的核心循环（同步存入玩家数据）
11. **基础敌对生物** — 给生存模式提供挑战（同步定义实体序列化）
