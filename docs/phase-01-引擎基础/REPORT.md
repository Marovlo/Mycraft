## 实现细节

### 纹理图集系统

**架构**：`TextureAtlas` 类扫描 `assets/textures/blocks/` 目录下所有 PNG 文件，按文件名排序后打包成正方形图集。图集尺寸自动计算为能容纳所有 tile 的最小 2 的幂次正方形网格。

**纹理名称解析流程**：`BlockRegistry::registerDefaults()` 中每个方块使用 `BlockFaceTextureNames`（字符串名称），初始化时 `resolveTextures()` 将名称映射为图集 tile 索引，写入 `BlockFaceTextures`（uint16_t ID）。这样方块定义与图集构建解耦。

**UV 坐标**：`MeshBuilder::addFace()` 通过 `atlas_->getTileUV(texId)` 获取 `{uMin, vMin, uMax, vMax}` 归一化坐标，直接映射到四个顶点。

**纹理资源**：用 Python 脚本 `tools/gen_textures.py` 程序化生成 13 种 MC 风格 16×16 PNG，纯 Python 实现 PNG 写入（无依赖），可随时替换为真实纹理。

### 雾效

扩展 UBO 增加 `fogColor`、`viewPos`、`fogRange` 字段。片段着色器中计算片段到摄像机距离，在 `fogStart`（渲染距离-2个区块）到 `fogEnd`（渲染距离）之间线性插值到雾色。清屏色与雾色一致（天空蓝），视觉上区块边缘平滑消失。

### Tick 系统

`TickClock` 使用累加器模式：每帧累加真实时间到 `accumulator_`，每当累积超过 50ms 就消耗一次并触发 `gameTick()`。设有每帧最大 10 tick 的限制防止死亡螺旋。

游戏逻辑（输入处理、物理、区块加载/卸载）全部移入 `gameTick()` 以固定 50ms 步长执行。网格构建和 UBO 更新保留在每帧执行（视觉相关，不影响游戏状态）。

## 阶段评估与后续调整建议

**当前状态分析**：引擎基础能力已满足进入第二阶段（核心生存玩法）的条件。纹理系统、雾效、Tick 系统、输入系统都已就绪。

**第二阶段准备情况**：
- 物品系统：可直接开始，无阻塞依赖
- 背包系统：需要 GUI 框架，建议第二阶段先做数据逻辑，GUI 渲染简化处理（快捷栏 HUD）
- 制作系统：依赖物品系统，串行开发
- 生命/饥饿：需要 HUD 显示，同上

**建议调整**：第八阶段的"GUI 系统"中，**HUD 的基础渲染能力**（文字+图标绘制）应该在第二阶段初期就建立最小可用版本，否则生命值、饱食度、快捷栏都无法可视化。建议第二阶段开头先做一个轻量级 HUD 渲染器（仅支持矩形+纹理块绘制），完整 GUI 系统仍留第八阶段。
