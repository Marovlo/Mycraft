# 第二阶段：核心生存玩法 — 详细开发文档

> **目标**：建立完整的物品→背包→制作→工具→战斗→生存循环。完成后玩家能在世界中"活下来"。  
> **前置条件**：第一阶段的纹理图集、Tick 系统、雾效已就绪。  
> **关键约束**：需要一个最小 HUD 渲染能力（从第八阶段提前），否则核心数据无法可视化。

---

## 实施批次与依赖关系

```
Batch 0: 最小 HUD 渲染器（前置，从第八阶段提前）
    │
Batch 1: 物品系统 + 物品注册表
    │
Batch 2: 背包 + 快捷栏（数据层 + HUD 显示）
    │
Batch 3: 方块交互增强（挖掘进度、掉落物、工具效率）
    │
Batch 4: 工具与武器系统
    │
Batch 5: 制作系统（工作台 + 配方）
    │
Batch 6: 生命值 + 自然伤害 + 死亡重生
    │
Batch 7: 饱食度 + 食物系统
    │
Batch 8: 护甲系统（可延后到第五阶段生物出现后）
```

## Batch 0：最小 HUD 渲染器

### 需求分析
第二阶段的多个系统需要在屏幕上显示信息：快捷栏、生命值、饱食度、准星。当前引擎只有 3D 管线，没有 2D 覆盖渲染能力。

### 实现方案
在现有 render pass 末尾（3D 方块之后），使用正交投影矩阵绘制 2D 四边形。不需要新管线 — 复用现有管线但切换 UBO 为正交投影、关闭深度测试。

更简洁的方案：新增一个独立的 2D 渲染管线（`ui_pipeline`），专门用于 HUD 和 GUI 绘制：
- 正交投影（像素坐标）
- 无深度测试
- Alpha blending 开启
- 使用同一个 render pass（不需要新通道）

### 最小功能集
- 绘制带纹理的 2D 矩形（用于快捷栏槽位、心形图标等）
- 绘制纯色矩形（用于选中框高亮、背景遮罩）
- 十字准星（屏幕中心 2 条交叉线段）

### 新增文件
- `src/renderer/ui_renderer.h/.cpp` — 2D UI 渲染器
- `src/shaders/ui.vert` + `src/shaders/ui.frag` — UI 着色器
- `assets/textures/ui/` — UI 纹理（准星、快捷栏框等）

### 数据结构
`UIRenderer` 收集每帧的 2D 绘制请求，在 render 回调末尾一次性提交。每个绘制请求是一个带 UV 和颜色的 2D 四边形。使用动态 vertex buffer 每帧更新。

## Batch 1：物品系统

### 核心设计
物品系统是方块系统的超集 — 每个方块类型对应一个物品（方块物品），但物品还包括工具、食物、材料等非方块物品。

### 数据结构

**ItemId**: `uint16_t`，和 BlockId 类似。方块物品的 ItemId 等于其 BlockId（简化映射）。

**ItemProperties**：名称、显示名、最大堆叠数、物品类型枚举（Block/Tool/Weapon/Food/Material）、关联的 BlockId（方块物品才有）、纹理 tile 索引、耐久上限（工具/装备才有）。

**ItemStack**：物品堆叠，包含 ItemId + 数量(count) + 当前耐久。空堆叠用 ItemId=0 表示。

**ItemRegistry**：单例，与 BlockRegistry 类似。启动时注册所有物品，O(1) 查找。

### 初始物品列表
第二阶段需要的物品（逐步注册）：
- 12 种方块物品（对应现有 12 种方块）
- 5 种工具 × 2 等级（木/石）= 10 种工具：木镐、木斧、木锹、木剑、木锄 + 石质版本
- 木棍（合成材料）

### 新增文件
- `src/core/item.h` — ItemId、ItemProperties、ItemStack、ItemRegistry 定义
- `src/core/item.cpp` — ItemRegistry 实现 + registerDefaults()

### 对现有代码的改动
- `block.h`：BlockProperties 增加 `ItemId dropItem`（被破坏时掉落的物品）和 `uint8_t dropCount`
- `player.h`：`selectedBlock` 将被替换为 `Inventory` + `selectedHotbarSlot`（Batch 2）

## Batch 2：背包与快捷栏

### 数据结构
**Inventory**：36 个 `ItemStack` 槽位的数组。
- 槽位 0-8：快捷栏（屏幕底部显示）
- 槽位 9-35：主背包（E 键打开时显示）
- 额外：4 个装备槽（头盔/胸甲/护腿/靴子）+ 副手槽（预留）

**Hotbar**：不独立存储，而是引用 Inventory 的前 9 个槽位。只持有 `selectedSlot`（0-8）索引。

### 交互逻辑
- 数字键 1-9：直接选中对应快捷栏槽位
- 滚轮上/下：`selectedSlot` 循环切换
- 左键放置/破坏：从快捷栏当前选中槽位取物品
- 方块破坏后掉落物品→尝试自动拾取到背包（找同类可堆叠槽位 → 找空槽位）

### HUD 显示
用 Batch 0 的 UIRenderer 绘制：
- 屏幕底部中央：9 个快捷栏格子（带物品纹理和数量）
- 选中格子高亮边框
- 屏幕中心：准星十字

### 新增文件
- `src/player/inventory.h/.cpp` — Inventory 类
- `src/ui/hud.h/.cpp` — HUD 渲染逻辑

### 对现有代码的改动
- `player.h`：添加 `Inventory inventory_` 成员，移除 `selectedBlock`，添加 `selectedHotbarSlot`
- `game.cpp`：`handleInput()` 中方块交互改为从背包取物品

## Batch 3：方块交互增强

### 挖掘进度系统
- 长按左键开始挖掘当前目标方块
- 挖掘时间 = `blockHardness * hardnessMultiplier / toolSpeedModifier`
- 每 tick 累加挖掘进度，达到 1.0 时方块破坏
- 切换目标方块或松开左键时进度重置
- 空手挖掘所有方块都可以但速度极慢（除 bedrock 等 hardness=-1 的方块完全无法挖掘）

### 挖掘阶段动画
方块被挖掘时表面叠加裂纹纹理（10 个阶段）。可以通过在方块顶部渲染一个略微膨胀的裂纹覆盖面实现，或者在片段着色器中混合裂纹纹理。

第二阶段简化实现：不做裂纹纹理，只做进度条（HUD 上小进度条或准星变色指示进度）。

### 方块掉落物
破坏方块后，根据 BlockProperties::dropItem 生成物品实体。

第二阶段简化实现：不做物品实体渲染和物理，方块破坏后直接将物品添加到玩家背包。后续阶段添加物品实体掉落/拾取。

### 工具效率
不同工具对不同方块有加速效果。在 ItemProperties 中定义 toolType（Pickaxe/Axe/Shovel/Sword/Hoe）和 miningSpeed。方块在 BlockProperties 中定义 requiredToolType（镐/斧/锹/任何）。

匹配的工具挖掘时间大幅缩短，不匹配则为基础速度（空手速度）。

### 新增文件
- `src/game/block_interaction.h/.cpp` — 挖掘状态机（目标方块、进度、工具检查）

## Batch 4：工具与武器系统

### 工具等级
每种材质定义：挖掘速度、耐久上限、攻击伤害、挖掘等级。

| 材质 | 挖掘速度 | 耐久 | 攻击力 | 挖掘等级 |
|------|---------|------|-------|---------|
| 木 | 2.0 | 59 | 4 | 0 |
| 石 | 4.0 | 131 | 5 | 1 |
| 铁 | 6.0 | 250 | 6 | 2 |
| 金 | 12.0 | 32 | 4 | 0 |
| 钻石 | 8.0 | 1561 | 7 | 3 |

第二阶段只实现**木和石**等级（铁需要熔炼系统，金/钻石需要矿脉生成，后续阶段添加）。

### 耐久消耗
每次使用工具（挖掘方块、攻击实体）消耗 1 耐久。耐久归零时物品从背包中移除。

### 武器
剑：攻击力高于其他工具。第二阶段暂无攻击目标（生物在第五阶段），但先实现数据结构和攻击逻辑框架。

### 对 ItemRegistry 的扩展
在 `registerDefaults()` 中注册工具物品，设置 toolType、miningSpeed、durability、attackDamage。

## Batch 5：制作系统

### 配方定义
每个配方包含：输入网格（2×2 或 3×3 的 ItemId 数组）+ 输出 ItemStack。

两种配方类型：
- **有形配方**：输入物品必须在指定位置（如工作台配方）
- **无形配方**：输入物品可以在任意位置（如木板→4木板）

### 配方匹配
遍历所有注册的配方，尝试与合成网格匹配。有形配方需要检查位置对应，无形配方只检查材料种类和数量。

### 初始配方
| 输出 | 输入 | 网格 |
|------|------|------|
| 木板 ×4 | 原木 ×1 | 无形 1×1 |
| 木棍 ×4 | 木板 ×2（竖排） | 有形 1×2 |
| 工作台 | 木板 ×4（2×2） | 有形 2×2 |
| 木镐 | 木板 ×3 + 木棍 ×2 | 有形 3×3 |
| 木斧 | 木板 ×3 + 木棍 ×2 | 有形 3×3 |
| 木锹 | 木板 ×1 + 木棍 ×2 | 有形 3×3 |
| 木剑 | 木板 ×2 + 木棍 ×1 | 有形 3×3 |
| 石质版本 | 圆石替换木板 | 同上 |

### 合成界面
- 2×2 合成格：背包界面内（E 键打开）
- 3×3 合成格：右键工作台方块打开
- 拖拽物品到合成格 → 实时显示输出 → 点击输出取走并消耗材料

### 新增文件
- `src/crafting/recipe.h/.cpp` — Recipe 定义和 RecipeRegistry
- `src/ui/crafting_screen.h/.cpp` — 合成界面（可延后，先用简化方式）

第二阶段简化：先不做完整 GUI 合成界面，而是用快捷键触发"自动合成"（选中原材料按特定键自动匹配配方并产出）。完整拖拽式 GUI 在第八阶段实现。

## Batch 6：生命值与自然伤害

### 生命值系统
- 最大 20 HP（10 颗心）
- HUD 显示：10 个心形图标，每颗心 = 2HP
- 半心显示：损失奇数 HP 时显示半颗心

### 自然伤害源
| 伤害源 | 伤害值 | 触发条件 |
|--------|-------|---------|
| 摔落 | (距离-3) 点 | 下落超过 3 格 |
| 溺水 | 2/秒 | 水下空气耗尽 |
| 岩浆 | 4/半秒 | 接触岩浆方块 |
| 虚空 | 4/半秒 | Y < -64 |
| 仙人掌 | 1 | 接触仙人掌方块 |

第二阶段实现：摔落伤害（已有下落速度数据）+ 虚空伤害。其他伤害源随后续方块和系统添加。

### 摔落伤害实现
在物理系统中追踪下落起始高度。当 `onGround` 从 false 变为 true 时，计算下落距离。超过 3 格则造成 `(距离 - 3)` 点伤害。

### 死亡与重生
- HP 降至 0 时触发死亡
- 死亡后：清空背包物品（掉落在死亡点，简化版先直接消失）、显示死亡屏幕（"You died!"）
- 按键重生：恢复到出生点或最后使用的床（床系统后续实现），满血满食

### 新增文件
- `src/player/health.h` — 生命值组件（可内嵌到 Player 中）

### 对现有代码的改动
- `player.h`：添加 hp, maxHp, fallStartY 等字段
- `physics.cpp`：添加摔落伤害检测
- HUD：显示心形图标

## Batch 7：饱食度与食物

### 饱食度系统
- 最大 20 点（10 个鸡腿）
- 隐藏饱和度：额外缓冲值，初始 5.0
- 消耗顺序：先消耗饱和度，再消耗饱食度
- 消耗动作：跳跃(-0.05)、冲刺(-0.1/tick)、攻击(-0.1)、挖掘(-0.005/tick)

### 饥饿效果
- 饱食度 ≥ 18：缓慢回血（每 80 tick 回 1HP）
- 饱食度 ≤ 0：持续扣血（每 80 tick 扣 1HP，不低于 1HP）

### 食物物品
| 食物 | 回复饱食度 | 回复饱和度 |
|------|-----------|-----------|
| 苹果 | 4 | 2.4 |
| 面包 | 5 | 6.0 |
| 生猪排 | 3 | 1.8 |

第二阶段简化：先实现苹果（树叶有概率掉落苹果），其他食物随后续合成和生物系统添加。

### 进食机制
右键持续按住 1.6 秒（32 tick）消耗食物，回复对应饱食度和饱和度。只有饱食度不满时才能进食。

### 新增文件
- `src/player/food.h` — 饱食度组件

### 对现有代码的改动
- `player.h`：添加 hunger, saturation 字段
- `item.h`：食物物品添加 hungerRestore, saturationRestore 属性
- HUD：显示鸡腿图标

6. **Batch 5**：制作 → 简化合成（快捷键触发）
7. **Batch 6**：生命值 → HP + 摔落伤害 + 死亡重生
8. **Batch 7**：饱食度 → 食物 + 饥饿效果
